# url-diff

Compare two URLs — decode base64/base64url parameters, extract readable strings from binary blobs (protobuf, etc.), identify structural differences field-by-field, and suggest remediation.

## Description

Decodes and diffs URL parameters that contain binary-encoded data (base64url protobuf, nested tokens, etc.). Produces a human-readable table of differences and explains what each difference means. Used primarily to diagnose discrepancies between Google Flights deep-link URLs generated by this app vs. URLs from other sources.

## Input

Two URLs to compare, provided as plain text or as a user message. Optional context about which parameter to focus on (default: all query parameters).

## Steps

### 1 — Parse query parameters from both URLs

Split each URL on `?` and then on `&`. For each param, collect `key=value` pairs. Report any params that appear in one URL but not the other.

### 2 — Identify base64/base64url params

For each param value:
- Try standard base64: `Buffer.from(val, 'base64')`
- Try base64url (replace `-`→`+`, `_`→`/`, add `==` padding): `Buffer.from(val.replace(/-/g,'+').replace(/_/g,'/') + '==', 'base64')`
- If the decoded buffer is > 50% printable ASCII, treat it as a nested string and repeat from step 1.
- Otherwise treat it as binary (likely protobuf).

Use `node -e` with inline JS to do the decoding:

```js
const b = Buffer.from(val, 'base64');
// extract printable strings >= 3 chars
let cur = '';
for (const c of b) {
  if (c >= 32 && c < 127) cur += String.fromCharCode(c);
  else { if (cur.length >= 3) console.log(cur); cur = ''; }
}
if (cur.length >= 3) console.log(cur);
```

### 3 — Parse protobuf fields (for binary blobs)

Walk the buffer byte-by-byte interpreting protobuf wire-format tags:
- `tag & 7 === 0` → varint: read until byte with bit-7 clear, compute value
- `tag & 7 === 2` → length-delimited: next byte(s) = length, then read that many bytes
- Field number = `tag >> 3`

```js
function parseProto(buf) {
  let i = 0;
  const fields = [];
  while (i < buf.length) {
    // read varint tag
    let tag = 0, shift = 0;
    while (true) { const b = buf[i++]; tag |= (b & 0x7f) << shift; shift += 7; if (!(b & 0x80)) break; }
    const fn = tag >> 3, wt = tag & 7;
    if (wt === 2) {
      let len = 0, s2 = 0;
      while (true) { const b = buf[i++]; len |= (b & 0x7f) << s2; s2 += 7; if (!(b & 0x80)) break; }
      const val = buf.slice(i, i + len); i += len;
      fields.push({ fn, wt, val, str: val.every(b => b >= 32 && b < 127) ? val.toString() : null });
    } else if (wt === 0) {
      let v = 0, sh = 0;
      while (true) { const b = buf[i++]; v |= (b & 0x7f) << sh; sh += 7; if (!(b & 0x80)) break; }
      fields.push({ fn, wt, val: v });
    } else break; // unknown wire type — stop
  }
  return fields;
}
```

### 4 — Diff the decoded fields

Compare parsed field arrays from both URLs. For each field number:
- Same value in both → note as "identical"
- Different value → show `URL1: <val>  URL2: <val>` and explain the semantic difference

For Google Flights `tfs`:
| Field | Meaning |
|---|---|
| root.1 | Trip type constant (28) |
| root.2 | 1 = one-way, 2 = round trip |
| root.3 (repeated) | LegGroup — one per leg |
| root.8 | Passengers |
| root.9 | Cabin class |
| LegGroup.2 | Leg departure date |
| LegGroup.4 (repeated) | Segment |
| LegGroup.13 | Departure AirportNode |
| LegGroup.14 | Arrival AirportNode |
| Segment.1 | Departure IATA |
| Segment.2 | Segment date |
| Segment.3 | Arrival IATA |
| Segment.5 | IATA carrier code (when split from flight number) |
| Segment.6 | Flight number digits (or combined `IATA NNNN` if field 5 absent) |

For Google Flights `tfu`:
| Field | Meaning |
|---|---|
| outer.1 | Session/fare cache token (opaque blob) |
| outer.2 | Sub-message: field 1 = some flag |
| outer.4 | Empty (present as sentinel) |
| inner.1 | Opaque session key string |
| inner.2 | Fare key, e.g. `LH759\|4Y50#1` (flights + pax count) |
| inner.3 | Price sub-message: field1=amount(cents), field2=decimals, field3=currency |
| inner.7 | Result rank/position |
| inner.14 | Price (duplicate of inner.3.field1) |

### 5 — Identify differences and classify them

For each difference found, classify:

| Class | Example | Impact |
|---|---|---|
| **Encoding style** | Carrier in field 5 vs combined in field 6 | Cosmetic — GF accepts both; our app uses split encoding |
| **Missing fare token** | `tfu` absent | GF will re-fetch price; URL is still valid |
| **Date difference** | Segment.2 differs | Different itinerary date — genuine routing change |
| **Airport difference** | Segment.1 or .3 differs | Different origin/destination |
| **Flight number difference** | Segment.6 value differs | Different flight number |
| **Trip type** | root.2 = 1 vs 2 | One-way vs round trip |

### 6 — Remediation suggestions

Based on the diff class:

- **Encoding style (carrier split vs combined)**: No fix needed. Both are valid. If generating for compatibility with a specific source, note which encoding that source uses. Our app always uses split encoding (field 5 + field 6) which matches live GF booking URLs.

- **Missing `tfu`**: If a cached price token is desired, the token must come from a prior GF search response or SerpAPI result. Cannot be fabricated client-side. URLs without `tfu` are fully functional.

- **Date/airport/flight differences**: Identify the source of truth (SerpAPI normalized data vs manually entered), fix the field in the itinerary object before calling `buildGoogleFlightsDeepLink`.

- **Wrong trip type flag**: Ensure `returnIt` argument to `buildGoogleFlightsDeepLink` is non-null for round trips.

- **Segment field 5 missing when expected**: In `googleFlightsLink.ts`, `airlineCodeFromSeg` may fail to parse the carrier code. Common cause: IATA codes that start with a digit (e.g. Condor `4Y`, World2fly `2W`) are not matched by a `[A-Z][A-Z0-9]` pattern. The regex must also cover `[0-9][A-Z]`. Similarly `flightNumOnly` must strip digit-starting carrier prefixes via a full carrier-prefix regex rather than `replace(/^[^0-9]*/, '')` (which stops stripping at the first digit and leaves the whole string intact for codes like `4Y 51`). Fixed in `googleFlightsLink.ts` as of commit after 909da6b.

## Example invocation

When a user asks to compare two GF booking URLs, run:
1. `node -e` to decode both `tfs` params and print readable strings
2. `node -e` to parse protobuf fields from both
3. Byte-diff the two buffers
4. Decode the `tfu` param if present
5. Produce a table of differences with classification and remediation
